# 强化学习前沿论文调研与改进建议

调研日期：2026-10-18（北京时间）。适用背景：已学习 PPO、GRPO、Agentic RL，正在搭建手写 GRPO 实验项目 ReasoningForge；当前本机为 6GB RTX 3060 Laptop GPU。

> 建议先选择一个可证伪的问题：相同计算预算下，怎样获得更多有效学习信号？可以从数学 RLVR 继续，也可以转向 Agent 探索、世界模型或自博弈课程。不要同时堆叠所有方法。

## 1. 先看建议：三条主线，八个可选方向

| 主线 | 适合回答的问题 | 推荐程度 | 与当前工程的关系 |
|---|---|---|---|
| 数学 RLVR 的采样与优化效率 | 同样生成 token，怎样学得更好？ | 最容易形成近期实验 | 可直接改 ReasoningForge |
| Agent 的失败轨迹与信用分配 | 都失败了，怎样辨别值得鼓励的行为？ | 想继续 Agent RL 时优先 | 需要多轮环境与轨迹接口 |
| 世界模型与自博弈课程 | 怎样主动获得经验、构造有用任务？ | 想拓宽 RL 基础时优先 | 适合独立小环境，不必使用大模型 |

具体方向按投入和先决条件排列：

| 编号 | 方向 | 首个实验的成本 | 成果应如何定位 |
|---|---|---|---|
| A1 | 优势标准化与长度分母的受控消融 | 低，不增加模型 | 已有方法复现、机制解释 |
| A2 | 总 token 预算约束下的动态采样与难度调度 | 中，主要增加采样管理 | 最推荐的当前项目研究问题 |
| A3 | 截断感知的训练与长度控制 | 低到中 | 先复现 DAPO，再验证小模型边界 |
| A4 | 哪些 token 值得更新：熵筛选与保底更新 | 中，不需要额外教师 | 已有方法迁移、适用边界研究 |
| A5 | LoRA 条件下的轨迹复用与策略漂移 | 中，控制额外反传次数 | 优化器机制与计算效率研究 |
| B1 | 从全失败 Agent 轨迹中恢复探索信号 | 中，需要可复现小环境 | 可以独立发展成 Agent RL 项目 |
| B2 | 乐观世界模型：促进探索还是利用模型错误？ | 小状态空间可低成本 | 真正超出 LLM 微调的 RL 主线 |
| B3 | RL 出题器：选择可学任务，而不是追逐噪声 | 小原型中等，完整论文昂贵 | 自博弈与自动课程项目 |

**我的优先建议：**留在当前项目就选 **A2**，用 A1/A3 建立可靠对照；转向 Agent 就选 **B1**；想系统理解更广义强化学习就选 **B2**。A4/A5 应在诊断到实际问题后再做。B3 适合愿意投入更长时间的独立选题。

下文的实验是假设和设计，不是已经获得的结果，也没有保证产生论文级创新。

### 2.3 不把大模型论文的收益直接搬到这里

现有条件是0.5B/1.5B、LoRA、短生成预算和6GB显存。多篇论文使用7B以上模型、长达数千 token 的回答或多GPU训练。它们说明某种机制值得研究，**不能证明当前组合一定有效，也不能保证官方权重已经能在本机完成该配置训练**。

目前工程的验证是随机小模型通路验证，尚没有真实 GSM8K/MATH 提升结果。应先补真实基线，再选择改动。

## 4. A1：优势标准化与长度分母，先做最干净的四组实验

**研究问题：**小模型 LoRA 中，观察到的变化究竟来自难度重加权、回答长度权重，还是单纯梯度尺度改变？

设第g道题的第i条回答奖励为R，组均值为μ，组标准差为σ：

$$
A^{std}_{g,i}=\frac{R_{g,i}-\mu_g}{\sigma_g+\epsilon},\qquad
A^{center}_{g,i}=R_{g,i}-\mu_g.
$$

设有效回答长度为T，逐token损失为ℓ，回答总数为N，固定生成上限为L：

$$
L_{sequence}=\frac1N\sum_i\frac1{T_i}\sum_t\ell_{i,t},\qquad
L_{fixed}=\frac1{NL}\sum_i\sum_t\ell_{i,t}.
$$

本项目已有的 `token` reduction 是除以实际有效token总数，**不等于固定分母 Dr.GRPO**。Dr.GRPO 已研究去掉两类归一化，并有Qwen2.5-1.5B的直接对照，因此这是很合适的复现起点。[Dr.GRPO 原文](https://arxiv.org/html/2503.20783v2)

| 实验 | 优势 | 长度分母 |
|---|---|---|
| N0 | 组内std | 每条回答的T |
| N1 | 只减组均值 | 每条回答的T |
| N2 | 组内std | 固定L |
| N3 | 只减组均值 | 固定L |

接入点是 `group_advantages()` 和 `grpo_loss()`；暂不改变采样器与奖励。主消融建议四组统一使用`beta=0`：当前loss把policy与KL一起归一化，若只保留同一个beta，改变长度分母也会改变KL加权；去std还会改变policy相对KL的强度。另一种做法是将KL单独按统一分母计算，再固定它的系数。含KL的结果另作对照，不与默认`beta=0.02`混称同一基线。新增 `fixed_length` 等配置仅为设计建议，当前代码尚不接受这些新字段。

记录正确/错误回答各自长度、截断率、按组正确比例分桶的贡献、梯度范数和独立验证集分数。除原学习率对照外，可以增加预先定义的尺度匹配对照，避免将分母引起的步长变化当成学习机制优势。

**何时值得继续：**变化在不同seed上可重复，且不是单纯放大/缩小更新强度。**失败也有价值：**若0.5B LoRA没有文献中的长度现象，可以报告适用边界。此方向本身不能包装成新算法。

## 5. A2：预算约束下的有效组采样，最适合当前项目

**研究问题：**给定同样的总生成token预算，应继续在这道题上采样，还是换一道题？

### 5.1 先补 Dynamic Sampling 基线

当前每道题采G条，全部进入训练。二元奖励的全0/全1组，正确性优势都为0。DAPO的动态采样会筛掉同奖励组，再补采有效组；它减少的是每次更新里的低信息组，不自动减少总生成开销。[DAPO](https://arxiv.org/abs/2503.14476)

首先实现：整组筛选、补采、尝试次数上限、总生成token上限、耗尽时退出策略，并保存数据游标和预算状态。必须统计被丢弃轨迹的成本。beta>0时零优势组仍可能贡献KL，筛掉它们也会改变正则化的采样分布，应单独说明。

### 5.2 然后做SARA式“先看少量，再决定继续”

SARA使用成功率的Beta后验和短probe判断是否值得继续；其默认成功保留的组仍采满G，变量组早提交是另外的消融。这样比一开始就改成可变G更接近现有代码接口。[SARA 原文](https://arxiv.org/html/2607.26253v1)

若单条回答成功率为p，G条独立采样出现混合正确性组的概率为：

$$
P_{mixed}=1-p^G-(1-p)^G.
$$

这是理解调度的简化模型，不是假定已知真实p。实际根据历史与probe更新后验：probe已混合就继续；仍全部失败/成功时，估计余下采样产生混合组的机会，再决定补齐或换题。停止规则会改变训练分布，不能未经分析就宣称估计仍无偏。

**建议的三个对照：**固定G均匀采样；完整组Dynamic Sampling；probe后选择是否补齐。三者固定相同G、最大回答长度、初始模型和总生成token预算，另报告总时间。

主要指标：验证pass@1/pass@8、有效组/万生成token、被丢弃token比例、各难度桶覆盖率、额外调用数和墙钟。若只减少优化器步数却花了更多时间，应如实报告。

### 5.3 可继续扩展为难度与主题覆盖共同调度

VIP将预测成功率转成rollout分配；ADS进一步考虑语义簇与难度边界。VIP的理论设置与标准GRPO不完全相同；ADS需要参考解，不能把最终答案NLL冒充整段解答NLL。[VIP](https://arxiv.org/html/2602.01601v3)、[ADS](https://arxiv.org/html/2606.22305v2)

适合你的**待验证设计**是：按训练历史估计难度，保留一部分均匀探索，其余预算给当前有望学会的题，同时约束各主题覆盖。先用题型标签或少量簇，避免完整GP和大规模表示预处理。保留均匀份额能否避免难题长期失访，需要和纯难度调度比较；它是研究假设，不是已证明的创新。

**退出条件：**若基座在审计样本上几乎全错且输出经常未完成，先调整题目难度或生成预算。调度无法保证凭空得到正确答案。

## 6. A3：截断感知训练，分清“不会算”与“没写完”

**研究问题：**短预算下的负奖励，有多少其实来自答案未完成或缺少最终标记？

当前 `truncated` 只用于日志：未出现EOS且耗尽预算的前缀仍进入loss。它不代表语义上一定错误；同样，恰好达到长度上限也不应直接等价于截断。

第一轮做三个对照：原样保留；截断轨迹不计policy loss；长度上限前的缓冲惩罚。后两项对应DAPO已有设计，须明确各自处理的是屏蔽还是奖励，不混为一个开关。[DAPO 超长处理](https://arxiv.org/html/2503.14476)

接入点：`prepare_window()`处理训练资格/奖励，`grpo_loss()`处理独立loss mask。主对照先按原始完整G计算优势，再屏蔽截断回答的policy项；删除回答后重算优势是额外实验因素，不能混入。**不要把用于Attention的mask一起清零**，也不能删几条后继续用原G做`view`。整窗无policy样本时统一跳过优化、照常记录生成成本；是否允许KL-only更新须另行定义，主实验不暗中启用。

保留原始正确性奖励，另记长度惩罚；评测始终使用原正确性。分桶查看“正确且截断、错误且截断、正常结束”，并在统一的更宽评测预算下复核，防止只学会更早结束。

后续可以验证“只在正确解之间偏好较短解”，但它改变优化目标，需要独立消融；不能认为短答案必然意味着更好的推理。若验证正确率下降，长度节约本身不能算成功。

## 7. A4：高熵token选择，研究它为何有效而非盲用20%

Beyond 80/20已经研究只更新高熵少数token；其主要证据来自Qwen3-8B/14B/32B。**只让20% token计入loss，不等于节省80%算力**：生成、Transformer前向和上下文依赖仍在，回答还可能变长。[论文](https://arxiv.org/html/2506.01939v2)

GEPO则从prompt组的熵出发，非对称调整正负优势，并用历史统计自适应阈值。因此“用熵控制优势”也已有先例，且不能认为越高熵越好。[GEPO](https://arxiv.org/html/2607.16850v1)

**你的问题可以更具体：**在0.5B LoRA和短回答中，高熵位置真比随机位置更有学习价值吗？

| 对照 | policy gradient使用的token |
|---|---|
| E0 | 所有有效回答token |
| E1 | 最高熵20% |
| E2 | 随机20% |
| E3 | 最低熵20% |

按整个优化窗口或预先约定的组内范围计算阈值，不要让每个micro batch自行挑选后改变实验含义。四组使用明确且可比较的loss分母，另检查尺度效应。

当前 `compute_token_stats(..., return_entropy=True)`已有逐token熵。可先把采样时的熵固定下来作为选择依据，避免每次复用更新都重选造成额外变量；若改成实时熵选择，要单列对照。这是建议设计，不是论文原配方的完整复现。

Attention依然看完整上下文；policy loss使用选择mask；KL是否覆盖全部有效token要事先固定。设计上需分离`attention_mask / policy_mask / kl_mask`，当前单mask接口还不支持。全窗口筛选可能让某条回答没有选中token：其policy贡献为0，token reduction按全窗选中token数归一；若使用sequence reduction，应明确仍保留原回答数N，不能靠删除零行悄悄重加权。KL按自己的mask与统一分母计算；整窗无policy token时按预定规则跳过。EOS和最终答案区域可做“保底保留”扩展，但须对比随机等量保留，不能因为额外保留更多token就归功于语义设计。

**成功证据：**高熵组稳定优于等数量随机组，且收益不是更多生成token换来。否则应优先考虑更新强度或正则化解释。

## 8. A5：轨迹复用、序列比率和低秩更新的关系

**研究问题：**LoRA只更新少量参数时，同一批轨迹复用多少次值得？怎样在采样成本与策略漂移之间取舍？

当前已有 `updates_per_rollout`。如果新rollout在全部梯度累积后只做一次step，更新前新旧参数相同，ratio≈1，clipping通常尚未激活；复用后才有机会观察差异。相同优势和分母下，多种目标的初次梯度可能相同或只差尺度。

GSPO使用回答内log-ratio的平均再指数化：

$$
s_i=\exp\left(\frac1{T_i}\sum_t[\log\pi_\theta-\log\pi_{old}]\right).
$$

它是几何平均比率，不是将token概率直接连乘，也不是逐token裁剪后平均。SAPO改用平滑的自适应门控；DHPO混合token/sequence信息。它们的裁剪/温度尺度不同，不能统一套ε=0.2后宣布公平。[GSPO](https://arxiv.org/html/2507.18071v2)、[SAPO](https://arxiv.org/html/2511.20347v2)、[DHPO](https://arxiv.org/html/2601.05607v1)

先只做GRPO复用1/2/4次，再按诊断选择GSPO或SAPO之一。保持优势和loss分母一致，避免一次改动多个因素。Revisiting Entropy已研究更新次数与熵，**“少更新防塌缩”本身不是新结论**。[相关研究](https://arxiv.org/html/2511.05993v3)

增加正/负优势分项clip比例、log-ratio分位数、按长度分桶的漂移。ratio均值接近1不能排除尾部极端值，熵也不能替代独立正确率。

一个可检验扩展是：根据预先约定的漂移或有效裁剪阈值停止复用，将剩余计算转给新采样。对照必须同时报告新生成token、训练处理token和时间，不能只按step比较。若LoRA漂移一直很小，应承认自适应停机没有触发，而不是人为放大学习率制造优势。

当前同步共享模型的实验研究的是轨迹复用，**不是异步推理引擎权重滞后**。采样保持`temperature=1,top_p=1,top_k=0`，先避免行为分布与原始logps不一致的额外问题。

## 9. B1：失败轨迹还能学什么？转向小型Agent环境

这条路线可以脱离当前单轮数学项目。在已学习 Agent RL 的基础上，下一步可把“工具调用次数”转成更严格的环境行为与反馈。

HGPO解决步骤比较时的历史上下文不一致：同一observation在不同历史中，正确动作可能不同。CovGPO则只在全零结果组中利用首次访问覆盖差异。特别注意，CovGPO新版把覆盖作为探索代理，**不是已知到目标距离，也不保证逃出所有全失败情形**。[HGPO](https://arxiv.org/html/2602.22817v1)、[CovGPO v2](https://arxiv.org/html/2607.22724v2)

**可做的小环境：**若干房间、钥匙、门和目标物；动作是检查、移动、拾取、开门，环境输出结构化observation，结果由程序验证。先用离散小策略跑通，再换0.5B输出动作。包含死胡同、循环和部分可观测情况，使盲目探索不一定有价值。

比较：仅终局成功奖励；总是奖励新状态；仅全失败组加入首次访问信号；有真实可得子目标时的子目标奖励。单独增加历史一致分组实验，不要同时更换所有信用分配规则。

观察首次成功所需交互、终局成功率、重复/无效动作、覆盖率、步数、环境调用总量。用环境内部目标距离作诊断可以，但若任务本身拿不到该信息，就不能偷偷把它加入训练奖励。

**适合进一步研究的假设：**在存在死胡同或无关新状态时，单纯覆盖奖励会失效；条件式fallback、观察去重和历史一致性是否能缓解？这些机制都有相关先例，贡献可以是明确的失效条件和严格对照，而非给组合起新算法名。

实施时需要单独的`env.reset/step`、多轮rollout、action/observation mask和轨迹对齐。不能只换当前`math_reward()`就声称实现了Agent RL。

## 10. B2：乐观世界模型，补齐更广义强化学习视角

**研究问题：**学习一个偏向高回报的世界模型，是促进了真实探索，还是让策略钻模拟器的空子？

Optimistic World Models在真实数据的动力学拟合外，向模型转移分布加入基于优势的乐观目标与熵项，并在DreamerV3/STORM中验证。它不是把Actor换成一个更大的LLM，也不是PPO里的Reference Model。[OWM 原文](https://arxiv.org/html/2602.10044v1)

世界模型预测“执行动作后会发生什么”；策略预测“下一步做什么”。训练可以先在学习到的模型里想象，再用真实环境检查效果。

**低成本原型：**带随机滑移的稀疏奖励迷宫或chain，状态为少量离散变量，用小MLP/categorical分布学习转移。先做model-free Q-learning/PPO与普通Dyna式模型学习，再做受原论文启发的乐观动力学变体。这个缩小版本不是完整Dreamer复现。

固定真实交互预算，比较：普通模型拟合；只加模型熵；乐观更新；两者结合。统一想象步数，并同时报告模型训练/规划成本。

指标包括真实回报、首次成功交互数、预测误差、多步预测失真、想象回报与真实回报差距。再加入随机性或不可达高奖励状态，测试什么时候出现模型利用。

建议先使用已知终点奖励，再改成只从交互学习reward head。**如果所有已知与想象奖励都为0，优势目标本身不保证凭空产生探索方向**；还要解释奖励先验、熵或其他探索信号从哪里来。

这条线的价值在于掌握MDP、replay、模型误差与规划，能直接复用已有PPO知识，也不要求支付大模型训练成本。深度模型版本的经验结果不能直接当成所有小环境的收敛保证。

## 11. B3：RL出题与自博弈，选择“有学习价值”的任务

这里有两种不同路线，先选一个，避免同时训练两个复杂系统。

**路线一：环境可验证的任务课程。** Explorer-Zero让proposer实际执行环境轨迹，以中间/最终状态作为验证目标，再交替训练solver。无需人工任务标注，不等于无需环境、验证规则或预训练模型。原版的模型和硬件规模远超本机，不建议直接完整复现。[Explorer-Zero](https://arxiv.org/html/2610.19868v1)

缩小为本地工具环境：程序执行一条可行路径，构造终局目标和若干可验证checkpoint，再让solver完成。比较随机可解任务、只看最终完成、自适应难度、加中间checkpoint。先用程序出题器，后续才考虑RL proposer。测试集合必须固定且独立，不能用自己越来越容易的题证明进步。

**路线二：程序生成数据的课程。** Self-Play Pretraining中生成器用RL选择程序，学习器用CE预测输出；研究的是合成训练数据与迁移。原论文含小模型消融，但完整scaling预算很大，不能据“小模型”推断便宜。[论文](https://arxiv.org/html/2609.30063v1)

低成本版可把程序空间限制为受控DSL（递推、模运算、栈操作），用小策略出题、约百万参数学习器训练。对照随机课程、高loss奖励、学习进展奖励、梯度对齐奖励，并加入可控随机噪声。

问题聚焦：**高loss可能来自纯噪声，什么出题奖励还能选择可迁移的结构？** 在未见参数、组合和更长序列上测试，并将出题、执行、学习成本全部计入。学习进展和梯度对齐均有先例，真正的新证据应落在噪声、分布外组合或预算约束的具体边界。

## 12. 暂不作为第一步：过程奖励与BoT-GRPO

BoT-GRPO很新，但它需要外部token/步骤信号。数学实验使用过程评判，reward稳定性和额外调用成本都需要核算；论文自身也讨论了单seed、基准重叠和辅助奖励不保持原最优策略等限制。[BoT-GRPO 原文](https://arxiv.org/html/2610.09804v1)

当前只有最终答案0/1奖励，不能简单把它复制到token后就称为复现。若想尝试，先在能用程序定位步骤错误的小算术/代码环境构造有界信号，再比较相同奖励来源下的序列/步骤优势。不要先额外训练一个大型PRM，把资源问题和算法问题混在一起。

## 13. 一个很实用的工程改进：LoRA共享Reference基座

这不是新的RL算法，但对6GB显存很重要。当前beta>0会额外加载一份完整Reference。若基础权重完全冻结、LoRA不训练bias/额外保存模块，初始Reference可考虑通过临时关闭adapter计算，省去第二份基础权重。[PEFT官方`disable_adapter`](https://huggingface.co/docs/peft/v0.17.0/en/package_reference/peft_model#peft.PeftModel.disable_adapter)

必须验证与独立Reference的logps一致、关闭上下文可恢复、无梯度泄漏、保存恢复一致。这个替代不适用于基础权重已经被更新或Reference本来就带有不同adapter的情况。应报告峰值显存和吞吐，不能将省显存伪称准确率提升。

## 14. 怎样让实验结果可信且做得完

### 14.1 先完成真实基线

1. 冻结模型revision、代码commit、Tokenizer模板、LoRA层和验证器版本。
2. 使用真实训练/开发/测试划分，检查同题与近重复；16道演示题只检查通路。
3. 从训练或开发池固定抽取32道题，各采4条回答作诊断。记录正确率、最终格式成功率、截断率、混合组比例、显存峰值和吞吐。
4. 根据诊断确定可承受的回答预算。当前128 token可能限制完成率；先审计再决定256/512等设置，不保证本机每种配置都能训练。
5. 若几乎没有正确样本，先调整难度、预算或统一初始化方案。若增加SFT预热，所有比较方法必须使用同一新初始化。

### 14.2 用预算而不是步数约束比较

维护至少三本账：

- 新生成token：包含probe、补采、丢弃和所有失败轨迹；复用不重复计数。
- 训练处理token：每次反传都计数，反映reuse的成本。
- 真实耗时与显存：包含prefill、Reference、同步、验证器/环境调用；评估成本另列。

当前已有部分token指标，但没有完整预算停机和丢弃账本。`max_steps`只数优化器步数。先实现统计与预算，再比较采样效率。

**预算边界也要预先约定：**生成前不知道EOS以内的实际长度，可规定完整候选组/批结束后停，记录实际超额及由固定B、G、L给出的上界，并把真实token数作为横轴。不能临近上限时只给某个方法缩短L或改变G。probe已经花费的token同样计入；达到预算后不再接收新题，最后未满的有效训练窗口按实际样本归一，若没有有效组就跳过优化并正常退出。不同方法使用同一边界规则。

### 14.3 一个可调整的小预算顺序

| 阶段 | 内容 | 是否用于正式结论 |
|---|---|---|
| 诊断 | 固定32题×4回答，审计格式/截断/有效组 | 否，只决定可行性 |
| 初筛 | 选一个问题，最多3-4组，单seed；可从每组5万新生成token的机制检查起步 | 否，不保证如此少的预算能出现性能差异 |
| 复核 | 留下最有希望的1-2个改动，增加预算，至少3个训练seed | 可以报告不确定性，但仍需看规模与效果 |
| 最终评测 | 固定未调参的测试集、相同采样/长度/验证器，保留逐题输出 | 是 |

不预先承诺训练时长；先测本机tokens/s，再估算总预算。若评估开销超过训练，减少开发评估频率，不能删除正式独立测试。

### 14.4 判胜标准

优先比较相同预算下的heldout正确率，以及达到相近正确率所需成本。报告pass@1/pass@8、长度与截断、多seed离散程度；可按题配对bootstrap差值，每题的多个回答不是多道独立题。

调度方法必须报告主题/难度覆盖，不能因为挑更容易的训练题而用训练reward证明提升。熵、clip比例、覆盖率和过程分数都是诊断量，不代替最终任务成功率。

对于先导实验，无显著提升、未触发clip、覆盖与进展脱钩等结果也应保留；这能决定下一步，而不是只挑最好曲线。

## 15. 阅读顺序与最终选题建议

无需一次读完16篇。按目标只读一条路线：

- **继续数学后训练：**DAPO → Dr.GRPO → SARA → VIP/ADS → 根据诊断选GSPO/SAPO或Beyond80/20。
- **继续Agent：**已有AgentRL → HGPO → CovGPO最新版 → Explorer-Zero。
- **拓宽RL本体：**复习MDP与PPO的数据流 → OWM → 小环境模型学习/探索对照；对自进化更感兴趣再读Self-Play Pretraining。

可用的选题表述：

1. **单卡LoRA下数学RL的预算分配研究：**控制总生成token，比较均匀、Dynamic Sampling、短probe分配，分析不同难度与失败比例下的适用边界。
2. **稀疏奖励Agent的失败轨迹学习：**在含死胡同与重复状态的可验证环境中，比较条件式探索信号和历史一致信用分配，审计覆盖代理何时失效。
3. **模型式RL的乐观探索与模型利用：**在可控随机环境中，寻找乐观程度、模型误差和真实交互效率之间的边界。

以上可以成为受控复现和机制研究项目。若目标是论文创新，还需针对最终假设进一步查重，并通过新机制、理论或足够明确的新实证建立贡献；改一个loss、组合几个已有开关或迁移到小模型，本身不自动构成创新。
